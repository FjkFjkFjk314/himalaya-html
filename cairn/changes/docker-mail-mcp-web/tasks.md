# 实现计划

目标、部署边界和验收范围见同目录 `proposal.md`，预期行为见 `delta.md`。以下路径是拟议落点。每阶段通过对应验收后再依赖其产出。

## 1. 本机 Compose 与测试基线

- [ ] 在根目录新增 `Dockerfile`、`compose.yaml`、`.dockerignore`。用 Cargo.lock 构建，运行容器使用非 root 用户。Compose 默认不发布邮箱执行器或应用内部端口，分别定义 Web、MCP 和审批入口的网络边界。
- [ ] 在 `deploy/examples/` 增加占位账号配置和 secret command 示例。将真实配置、OAuth token、认证数据库、证书、TLS 私钥和测试邮箱参数放到仓库外。为 build context 与 Git 加排除规则，为公共 CI 加入脱敏的凭证扫描和合成邮箱测试。
- [ ] 验证 `docker compose config --quiet`、镜像构建、持久卷重启及文件权限。在合成账号验证结构化读取与 SMTP 投递。运行 `cargo test --locked --test mcp` 核对现有 MCP 合约。

## 2. 多账号 MCP 与权限

- [ ] 新增 `src/mail_service/`，维护受控账号别名、账号和文件夹作用域、工具与参数允许列表。复用 `src/mcp.rs` 的工具定义、固定账号会话和能力映射。以受限进程或内部接口调用，严禁把工具参数拼成 shell 命令。
- [ ] 新增 `src/mail_service/gateway.rs`，提供本机 stdio 和私有 HTTPS Streamable HTTP。确认目标客户端支持配置独立 Bearer 凭证和 TLS。仅支持 stdio 的客户端用本机入口。配置凭证撤销、轮换、请求体和附件大小、超时及并发限制。校验 Host 和提供的 Origin，关闭非必要跨域访问。
- [ ] 使用两个具有重叠邮件 ID 的账号验证切换、隔离和默认账号行为。在两种传输上用真实客户端走初始化、工具发现、读取和管理，核对无效或撤销凭证、跨账号请求、停用工具、隐藏参数和永久删除路径均被拒绝。测试一个后端失败时另一账号仍可用。

## 3. 发送策略与本机审批

- [ ] 新增 `src/mail_service/submission.rs`，对发送、回复、转发统一处理策略、快照、幂等键及发送状态。持久化审批和认领状态。请求正文变化必须生成新的快照与确认，结果未知时由管理员核对后处置。
- [ ] 新增本机审批页面，使用独立的本机监听和授权。提交审批使用非 GET 请求，检查 CSRF 和 Origin。审批页面显示实际发送的完整快照和发送结果，AI 令牌不能批准。Web 公网监听不发布审批路由。
- [ ] 用合成 SMTP 接收器测试直接发送、审批前零投递、拒绝、过期、篡改、重复确认、并发、服务重启及供应商超时。分别模拟请求已经受理和明确被拒绝。回复与转发验证正文、跟踪头和源附件归属，检查所有已知的工具参数旁路。

## 4. Web 只读阅读

- [ ] 新增 `src/mail_web/`，实现账号、文件夹、邮件列表和搜索、正文、附件五类读取页面或路由。分页沿用后端能力和 token，账号与文件夹由服务端验证。UI 不使用支持写入的 MCP 凭证。
- [ ] 用 HTML 净化、iframe sandbox 和 CSP 隔离邮件。首版支持受限的 CID 图片，根据同一邮件部件解析，限制允许的图片类型和大小。外链由用户主动打开，远程图片、脚本、表单、不安全 URL 和活动内容默认拦截。
- [ ] 用浏览器验证 HTML、纯文本、CID 图片、附件和仅 HTML 邮件。检查无未授权跨账号或附件访问，危险 HTML 无脚本执行或外连，浏览不会改变已读状态，邮件 API 拒绝写请求，退出后不能重新拉取邮件。

## 5. 公网 TCP 透传与本机二步验证

- [ ] 在 `deploy/examples/` 写出公网 L4 转发、私有网络授权、本机 TLS 和 Authelia 的占位配置。在部署文档说明单用户注册 TOTP、恢复方式和 DNS-01 自动续期。默认拒绝未知域名、来源及缺少二步验证的会话。
- [ ] 配置 Authelia `remember_me` 为 `30d`，保持 Web 路由使用 `two_factor` 策略。登录界面的记住选项默认不勾选，完整登录后才能用持久会话访问邮件。使用 `Secure`、`HttpOnly` 及适当 `SameSite` 属性的会话 Cookie，将服务端会话存储在本机并验证服务重启后可恢复。文档说明如何通过退出或管理员撤销使会话失效。
- [ ] 从公网独立设备验证域名证书和登录流程。检查无会话、仅输密码、过期会话、伪造转发身份、直接附件 URL 和后台地址。检查公网转发器仅建立 TCP 连接，公网主机缺少证书私钥且私网授权无法访问 MCP 或审批服务。验证本机下线失败方式和证书更新后的新连接。
- [ ] 用两个浏览器配置文件验证。勾选并完成两步登录后，原浏览器重开可免输密码和 TOTP，另一浏览器须完整登录。使用可控时钟或缩短的测试期限，检查期限从完整登录起算、重复访问不会续期，且截止后页面、API 和附件都要求重新登录。覆盖未勾选、只通过密码验证、退出、服务端撤销、清除 Cookie 和本机服务重启。确认记住的会话仅授权只读网页。

## 6. 五类邮箱验收与 Cairn 收尾

- [ ] 逐个使用授权测试账号运行下表。记录登录或令牌更新、分页、读信、附件、标记、移动、发送、回复和转发。确认测试收件端实际收到，核对 Sent 副本及已读状态。供应商能力差异和不可验证项逐项注明。
- [ ] 在同一套本机部署接入至少两个来自不同供应商的测试账号，跑通远端私有 MCP、本机审批和公网 Web。提交只含脱敏结果的报告，凭证和实际收件信息保存在部署环境。

## 子 session、subagent 与模型选择

- 为节省额度，简单任务默认使用 GPT-6.2 Sol，包括按已定方案编写阶段 1 的镜像和部署示例、阶段 5 的转发模板，以及整理合成测试数据和运行已有检查。能在当前会话完成的小改动可直接处理，避免重复派工。
- 共同的合成邮箱基线和读取接口定稿后，阶段 2 的 MCP 网关与阶段 4 的只读 Web 可分别交给独立子 session 并行推进。主 session 约定各自负责的文件、接口和验收项，再整合结果。
- 单个阶段内，范围明确、可独立验收的短任务可交给 subagent，简单任务显式选择 GPT-6.2 Sol。交回时附上改动位置和验证结果，方便所属 session 复核。
- 账号授权、浏览器会话、发送审批与幂等、跨入口权限隔离由主 session 负责设计和最终复核。子 session 或 subagent 遇到会改变这些约束的问题时，交回主 session 决定。
